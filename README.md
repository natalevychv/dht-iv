# DHT-IV in VHDL

VHDL implementations of the orthonormal discrete Hartley transform of type IV
(DHT-IV) for N = 3..8 in two architectures:

- **naive** - direct matrix-vector multiplication `Y = C(N) * X`,
- **proposed** - pipelined fast algorithms based on factorizations of `C(N)`
  that need far fewer multiplications.

Both architectures use the same fixed-point data types and are simulated side
by side with GHDL on the same test vectors.

The transform matrix is

```
c[k][n] = (1/sqrt(N)) * cas(pi * (2n+1) * (2k+1) / (2N)),   k, n = 0..N-1
cas(t)  = cos(t) + sin(t)
```

## Repository layout

```
src/common/          fixed_types_pkg.vhd - fixed-point types and helpers
src/naive/nN/        nN_naive.vhd - naive architecture (generated)
src/proposed/nN/     nN_prop_stageX.vhd - pipeline stages of the proposed algorithm
                     nN_prop_top.vhd    - top level connecting the stages
                     nN_coef_pkg.vhd    - coefficient constants (generated)
scripts/             Python generators (naive modules, coefficients, test vectors)
vectors/             nN_vectors.txt - test vectors (generated)
tb/                  testbenches: shared stimulus/checker + one nN_tb per N
sources/             per-target lists of VHDL files for run.sh
run.sh               GHDL compile and simulation script
```

Generated files are committed, so the simulation works without Python. Do not
edit them by hand - change the script and regenerate.

## Fixed-point format

All modules use `ieee.fixed_pkg` (VHDL-2008). Types are defined in
`src/common/fixed_types_pkg.vhd`:

| Type        | Format | Declaration              | Resolution (1 LSB) | Range       | Used for           |
|-------------|--------|--------------------------|--------------------|-------------|--------------------|
| `sfix32`    | Q15.16 | `sfixed(15 downto -16)`  | 2^-16 ~ 1.5e-5     | +-32768     | data path          |
| `sfix_coef` | Q1.30  | `sfixed(1 downto -30)`   | 2^-30 ~ 9.3e-10    | +-2         | constant coefficients |

- Additions and subtractions of `sfix32` values are exact; `resize32()` only
  removes the extra integer bit (with saturation).
- A product `sfix_coef * sfix32` has 46 fractional bits; `resize32()` rounds it
  back to Q15.16 (`fixed_round`, error <= 1/2 LSB) and saturates on overflow
  (`fixed_saturate`).
- Multiplications by `+-2^-k` are implemented as `shift_right`, which truncates
  the shifted-out bits (error < 1 LSB).

## Architectures

All modules have the same interface: `clk`, `rst`, `valid_in`,
`x : sfix32_vector(0 to N-1)`, `valid_out`, `y : sfix32_vector(0 to N-1)`.
Both architectures accept a new input vector every clock cycle; `valid` is
propagated through the pipeline.

**Naive** (`src/naive/nN/nN_naive.vhd`, generated by `scripts/gen_naive.py`):
entries `0` are skipped, `+-1` become additions, `+-2^-k` become shifts, all
other entries get one multiplier. Stage 1 computes the products, stage 2 sums
them with a balanced adder tree.

**Proposed** (`src/proposed/nN/`): one VHDL entity per pipeline stage; the
coefficients are passed to the stages as generics `C_COEF_S_k_N_G` from
`nN_coef_pkg`.

| N | Naive multipliers | Proposed multipliers | Naive latency | Proposed latency (stages) |
|---|-------------------|----------------------|---------------|---------------------------|
| 3 | 9                 | 2                    | 2             | 2 (A-B)                   |
| 4 | 16                | 6                    | 2             | 3 (A-C)                   |
| 5 | 25                | 7                    | 2             | 3 (A-C)                   |
| 6 | 18 (+ 8 shifts)   | 4 (+ 6 shifts)       | 2             | 4 (A-D)                   |
| 7 | 49                | 10                   | 2             | 4 (A-D)                   |
| 8 | 64                | 18                   | 2             | 4 (A-D)                   |

Latency is given in clock cycles.

## Scripts

The scripts need only Python 3 (standard library). Run them from the
repository root:

```
python3 scripts/gen_naive.py      # src/naive/nN/nN_naive.vhd
python3 scripts/gen_coefs.py      # src/proposed/nN/nN_coef_pkg.vhd
python3 scripts/gen_vectors.py    # vectors/nN_vectors.txt
```

Each script accepts a list of N (e.g. `python3 scripts/gen_coefs.py 4 6`);
without it all N = 3..8 are generated.

| Script              | Description |
|---------------------|-------------|
| `dht_common.py`     | Shared code: DHT-IV matrix, classification of matrix entries, constants. |
| `gen_naive.py`      | Generates the naive modules. `--report` prints operation counts only. |
| `proposed_coefs.py` | Coefficient formulas of the proposed algorithms, `COEFS[N]["S_k"]` = value of `C_COEF_S_k_N`. Edit this file to change a coefficient. |
| `gen_coefs.py`      | Generates the coefficient packages from `proposed_coefs.py`. `--report` prints the Q1.30 quantization error only. |
| `gen_vectors.py`    | Generates the test vectors. `--count C` random vectors per N (default 1000), `--seed S` (default 1). |

### Test vector format

One vector per line, `2N` integers separated by spaces; lines starting with
`#` are comments:

```
x0 .. x(N-1) y0 .. y(N-1)
```

All values are raw Q15.16 integers (value * 2^16, e.g. 65536 = 1.0). The first
N vectors are the unit vectors, the rest have inputs drawn uniformly from
[-1, 1]. The expected outputs are computed in double precision and rounded to
the nearest Q15.16 value.

## Simulation

Requirements: GHDL with VHDL-2008 support, GTKWave (optional).

```
./run.sh                  # list available targets
./run.sh <target> [wave]  # compile and simulate one target, optionally open GTKWave
./run.sh all              # simulate all targets and print a summary
./run.sh clean            # remove work/ and sim/
```

The script exits with a nonzero status when a simulation fails (an assertion
with severity `error` or higher), so `./run.sh all` can be used as a
regression test. Waveforms are saved to `sim/<target>.ghw`.

### Adding a target

`run.sh` derives everything from the target name:

- `sources/common.txt` is always compiled first,
- `sources/<target>.txt` lists the target's VHDL files in compilation order
  (packages before the entities that use them),
- the top-level testbench entity must be named `<target>_tb`
  (e.g. target `n3` -> entity `n3_tb`).

New targets can be added this way without modifying the script.

## Verification

Each testbench `tb/nN_tb.vhd` simulates the proposed and the naive module in
parallel:

- `tb/dht_tb_stim.vhd` reads `vectors/nN_vectors.txt` and applies one vector
  per clock cycle (full throughput),
- two instances of `tb/dht_tb_check.vhd` compare the outputs of each module
  with the expected values and print the maximum error in LSB.

A test fails when an output differs from the expected value by more than the
tolerance `TOL_PROPOSED` / `TOL_NAIVE`.

### Error bounds

The tolerances are analytic worst-case bounds, not empirical values. The
error of an output is bounded by the sum of the maximum errors of all
roundings on its path:

- 1/2 LSB per rounded product,
- 1 - 2^-k LSB per `shift_right` by k bits (truncation),
- a value used several times in an output (e.g. `p(5)` in `y(0)` for N = 7)
  counts with its multiplicity,
- the additions after the multipliers are exact, and every proposed algorithm
  has a single layer of multipliers, so no error is multiplied again,
- plus 1/2 LSB for rounding the expected value in the test vectors.

The quantization error of the Q1.30 coefficients is below 0.01 LSB and is
neglected. Since the outputs and the expected values are integers, the bound
is rounded down.

| N | Naive bound | Naive observed | Proposed bound | Proposed observed |
|---|-------------|----------------|----------------|-------------------|
| 3 | 2           | 1              | 1              | 0                 |
| 4 | 2           | 2              | 2              | 2                 |
| 5 | 3           | 2              | 3              | 2                 |
| 6 | 3           | 2              | 4              | 3                 |
| 7 | 4           | 3              | 6              | 4                 |
| 8 | 4           | 3              | 2              | 2                 |

The observed values are the maximum errors (in LSB) over 20 000 random
vectors.
